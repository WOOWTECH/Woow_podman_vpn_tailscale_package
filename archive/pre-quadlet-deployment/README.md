# `archive/pre-quadlet-deployment/` — the openclaw compose-era deployment layer

**Reference material. Not installed, not executed, not tested, and not the deployment path of this
repository.** Deploy this repository with `scripts/install.sh` (Quadlet + systemd). Everything
under `tree/` describes what came *before* that, and is kept only so the work is not lost.

本目錄為**歷史參考資料**，不是本倉庫的部署路徑，請勿執行；實際部署請用 `scripts/install.sh`。

`tree/` is a byte-identical copy of the host directory, minus the files listed under
*What was excluded* below. No preserved file was edited.

## Where it came from / 來源

Host `woowtechopenclaw`, directory `~/Woow_podman_vpn_tailscale_package`.

That directory was assumed to be a clone of this repository. It is not: it has **no `.git` at
all** — no remote, no history, no bundle — and the SHA recorded in its `.deployed-commit`
(`8daabacc647054328db1ceac2f1f935c76f43824`, preserved in `tree/`) does not resolve in this
repository or anywhere else in the WOOWTECH organisation. A file-by-file comparison against `main`
and an org-wide code search found this material in no git repository anywhere. It was live code:
`woow-tailscale-gateway.service` on that host ran `tree/scripts/resource_ownership.py` from this
directory in **two `ExecStartPre=` lines and one `ExecStopPost=`** on every start and stop, and a
drop-in `official-services.conf` ran `tree/scripts/apply-official-services.sh` as `ExecStartPost=`.

Extracted from the local backup
`~/.local/share/woow-openclaw-deployment-backup/20260913-234957/deployment-layer.tgz`
(sha256 `13b07d18c3f511e602f63ba4bcff17705cca5bcdd69ef063cf136ac0bf87778f`, captured 2026-09-13).
Nothing was read from, or changed on, the host to produce this directory.

## What it deployed / 部署內容

Not the node client this repository now ships, but a **service gateway**: a single
`woow-tailscale-gateway` container on the **host** network, driven by a hand-written
`Type=notify` / `Restart=always` unit whose `ExecStart=` is a literal `podman run …` pinned to an
**image ID**, not a tag (`tree/systemd/woow-tailscale-gateway.service.in`). It advertised
`svc:hermes`, `svc:od` and `svc:odoo` to the tailnet, each mapping `tcp:443` to a local endpoint
behind NPM (`tree/systemd/official-services.json`). The host's `.env.gateway` and
`.env.gateway.before-official` recorded the migration of `HEADSCALE_URL` from a self-hosted
headscale (`http://127.0.0.1:28080`) to Tailscale SaaS (`https://controlplane.tailscale.com`);
both are excluded below, but the whole delta is quoted there.

The reason the tree is 5 200 lines: a resource-ownership model that reconciles container, volume
and network ownership before the gateway is allowed to start (`resource_ownership.py`,
`service_ownership.py`), a live-cleanup routine that knows which CLI invocations actually work
(`live_cleanup.py`), a unit renderer (`gateway_unit.py`), a credential-shape scanner
(`secret_scan.py`), and an 11-file pytest suite of roughly 2 400 lines.

## What looks reusable / 可再利用之處

`tree/tests/fixtures/` is **hand-captured real CLI output**, and it is the most unusual kind in the
four repositories — it records what the tools *refuse* to do:

* `tree/tests/fixtures/cli/observed-cleanup-failures.json` — three observed failures with their
  real argv, return code and after-state: `headscale nodes delete --identifier 9` returns **0 while
  leaving the node present** (`--force` is a *global* Headscale flag, not a `nodes delete` flag);
  `podman network rm live-net` returns 2 with the network still present; `tailscale ping
  --type=peerapi` fails with `flag provided but not defined: -type`. Each is a bug this project
  shipped because a test double assumed the command succeeded.
* `tree/tests/fixtures/cli/headscale-0.29.3-force-help.txt` and `tailscale-1.102.0-ping-help.txt` —
  the help excerpts that prove the above, with the version they were captured from in the filename.
* `tree/tests/fixtures/cli/podman-4.9.3-network-inspect.json` — real `podman network inspect` output
  at 4.9.3: lowercase JSON keys (`name`, `id`, `subnets`, `labels`), `containers: {}` as an **empty
  object** rather than an absent key.
* `tree/tests/fixtures/service_ownership/*.inspect.json` — real `podman inspect` of the compose-era
  `npm-app` and `odoo18-web`, carrying both `Image` (the sha256 id) and `ImageName` (the pinned
  reference). Confusing those two is another bug this project shipped. `"HostIp"` appears here in
  its true 4.9.3 spelling as well.

**Assessment against the current tests.** The current suite has one fixture,
`tests/fixtures/toypark1234.env`, and no captured podman or tailscale output at all;
`tests/smoke.sh` reaches a live host instead. Two things here would strengthen it directly:
the **version-stamped CLI help captures**, which would let `tests/` assert that the flags
`scripts/*.sh` pass still exist in the pinned tailscale version without a network; and the
`podman-4.9.3-network-inspect.json` shape, which would let the network half of `scripts/install.sh`
and `uninstall.sh` be tested offline the way `Woow_podman_nginxpm` tests its inspect templates.
**Deliberately not done in this change** — preservation first; rewiring the live tests is separate
work that deserves its own review.

`tree/scripts/secret_scan.py` is also worth a look on its own: it splits its own pattern literals
so the scanner's source does not look like a credential to other scanners, and it never echoes a
match.

## What was excluded / 已排除的內容

No preserved file was modified; files that could not be preserved were dropped whole rather than
edited, so nothing under `tree/` is a partial or doctored version of a host file.

**Excluded for secrets (2 files)**

* `.env.gateway` and `.env.gateway.before-official` — the host's live gateway config. Inspection
  found **no secret value** in either: five keys (`GATEWAY_HOSTNAME`, `HEADSCALE_URL`,
  `HEADSCALE_CONTAINER`, `HEADSCALE_USER`, `STATE_VOLUME`) and a comment stating the file never
  contains an enrollment key. They are left out anyway because the tree's own
  `tree/.gitignore` classifies `.env.gateway` as "local env with secrets", and a file its author
  treated as secrets-class is not one to force past an ignore rule. Nothing is lost: the whole
  delta between them and the preserved `tree/.env.gateway.example` is
  `GATEWAY_HOSTNAME=woow-openclaw-services` and `HEADSCALE_URL`, which moved from
  `http://127.0.0.1:28080` (self-hosted headscale) to `https://controlplane.tailscale.com`
  (Tailscale SaaS) — the migration recorded in *What it deployed* above.

**Excluded as worthless (6 files)**

* `runtime/gateway-enrollment-id`, `gateway-node-id`, `gateway-self-id`, `last-verification.json`,
  `gateway.env` — host runtime state written by `deploy.sh`: node ids on that particular tailnet,
  the last verification timestamp, and the rendered env file. `tree/scripts/runtime_file.py` and
  `deploy.sh` describe exactly how each is produced.
* `scripts/__pycache__/image_id.cpython-312.pyc` — python bytecode cache.

**Excluded as already present (2 files)** — byte-identical to files already on `main`: `LICENSE`,
`examples/nginx-basic-auth.conf`.

A value-shaped secret scan over `tree/` (GitHub PATs, `sk-` keys, Slack tokens, AWS key ids, PEM
private keys and certificates, JWTs, tailscale/headscale auth keys, bcrypt and crypt hashes, and
non-placeholder `*PASSWORD|SECRET|TOKEN|_KEY=` assignments) reports **0 hits**. Three lines matched
the assignment pattern and were confirmed by hand to be the *pattern definitions* inside
`tree/scripts/secret_scan.py` and `tree/tests/test_secret_scan.py`, not values.
